## 路线原则

保持 Windows 优先的产品边界：在 WinUI 3/C# Manager 中配置游戏，再通过 Steam 调用独立 Rust Runner 启动。C# 配置服务、TOML、稳定数据路径与 CLI 继续作为基础。后续优先级是**玩家反馈 → Windows 交付与发布 → 可选更新与安全 Steam 集成 → 后续平台扩展**。

**将 v2 合入 main 是主线调整，不等于产品已经稳定发布。**安装／更新验收仍未完成。截至 **2026-10-02**，WinUI 是唯一 Manager：已按用户要求移除 Dioxus 应用、Rust `manager-core`、Dioxus Native E2E 和旧 UI 发布链。这改变了维护的实现，不代表尚未完成的 Windows 交付门槛通过。[Windows v2 设计](/SteamWrapper/zh-cn/project/design/windows-v2/)记录架构与最初阶段，[WinUI 评估](/SteamWrapper/zh-cn/project/decisions/winui3/)记录技术依据。下列里程碑明确验收顺序，不承诺日期，也不重新解释已发布版本号。限定范围的证据见[预览验收](/SteamWrapper/zh-cn/project/validation/winui/)。

## A. Windows 工具链与配置契约

- [x] 追溯原始需求、评估 WinUI、明确产品与架构边界
- [x] mise 固定开发工具，安装 MSVC/Windows SDK，完成独立 WinUI 自包含构建验证
- [x] 在 Windows 跑通现有 Rust Runner 的 6 项测试，包括 Job Object 与进程名等待
- [x] C# 读取/单字段编辑/Rust 消费验证：完整字段、缺省、旧别名键、未知数据、中文与路径参数
- [x] 配置原子保存、替换失败保留、备份和编辑冲突验证（非协作编辑器仍有最终检查竞态）
- [x] C# 生成配置交给真实 Runner fixture，验证 argv、cwd 和等待
- [x] 增量加入 Windows 构建与契约 CI，保留现有工作流；实现基线已通过远程 WinUI CI，后续改动仍需各自验证

上述 mise 环境准备是历史本机结果。mise 对贡献者是可选项；SDK 要求和直接 PowerShell/pnpm 命令见 [Windows 开发环境](/SteamWrapper/zh-cn/development/windows/)。

- [x] 已配置游戏首页、添加游戏、搜索与手动选择 Steam 路径

- [x] 安装/修复稳定 Runner，失败时保留配置与原二进制
- [x] 生成并复制精确启动项，明确原值保留和手动恢复引导
- [ ] 在 P0 中补齐更全面的原生交互、中文输入、键盘、缩放、取消和错误恢复验收

## C. Windows 可用预览与替换门槛

- [x] 关闭 Manager 后，从真实 Steam 启动/退出并记录状态与时长；本机 Unity 游戏与 9-nine 五部通过，见 [逐游戏证据与限制](/SteamWrapper/zh-cn/project/validation/steam/)
- [x] 本机第一部 CHS 启动器先退后，实际游戏与 Runner 继续等待至普通退出；中文开场及 Steam 时长通过，仅覆盖这个实际启动器场景

这些结果不证明所有启动器兼容、成就、干净系统安装、安全更新或卸载。剩余玩家与交付门槛列在下方 P0–P2。预览继续支持手动复制启动项：生成／复制不等于写入 Steam，fixture 通过也不等于真实 Steam 时长验证。

## 后续交付里程碑

| 优先级 | 交付目标 | 依赖与完成门槛 |
| --- | --- | --- |
| P0 | 原生 UI 自动化、玩家反馈、可用界面／错误提示和本地优先的可选封面 | 当前预览；限定范围的原生、离线和网络验收 |
| P1 | 自包含每用户安装器与 portable ZIP | P0 配置流程；干净 Windows 安装／更新／移动／卸载验收 |
| P2 | WinUI 预发布与稳定交付 | P1 产物；标签构建、校验和、双语说明及已核验的公告下载源；Authenticode 可选 |
| P3 | 可选应用更新 | P1 替换／恢复与 P2 可信发布元数据 |
| P4 | 安全 Steam 启动项应用／恢复 | P0 配置与 P1/P2 交付保护；不依赖 P3 |
| 后续 | 其他 Windows 目标及平台扩展 | 先保证 Windows 交付可靠；新增平台分别取得证据 |

P0 反馈和 P1 打包准备可以并行。WinUI 稳定发布需要 P0–P2 验收；P3/P4 尚未完成时，手动启动项仍受支持。可选更新检查和自动 Steam 写入不能推迟配置安全修复。

**当前部署契约的版本规则：**每个新可安装载荷／清单必须使用新的协调 `MAJOR.MINOR.PATCH`。只修改预览后缀会保留数字版本，因此安装正确拒绝同版本不同内容。当前协调源码为 `0.2.6`，公开的 `v0.2.5-preview.1` 早于这些交付修正。新数字版本支持真实载荷验收，不代表已发布稳定版。失败重试复用完全相同的不可变产物，不改写公开标签或放宽版本门槛。该规则不受 Authenticode 签名状态影响。

**版本保留兼容性：**冻结的 `0.2.1`／`0.2.2` 部署实现会拒绝安装根目录未知文件和 JSON 字段。当前实现复用原有暂存日志／恢复协议，不新增健康记录文件或状态字段；实际冻结辅助程序恢复／回滚夹具已在上述范围通过，但不代表完整旧 Manager UI 启动。不能推测上一版本历史健康状态，也不能为满足配额删除未知／隔离数据。

**交付修正前的历史缺陷：**卸载最多接受 32 个保留版本，安装既不清理也不限准入，长升级序列可能阻止卸载。当前源码在当前版本确认健康后的后续安装／修复中清理经核验的更旧版本，保留当前／上一版本；新安装可能暂留三个目录。未确认的历史保留，以 32 个版本准入上限及 32 MiB 日志预算拒绝扩张；旧安装卸载在同一字节上限内支持最多 1,024 个版本。这修复了源码级无限版本积累缺口，干净客户端及最终安装器验收仍未完成。

## P4. Windows 安全一键应用与恢复

**交付目标：**针对所选 Steam 用户的所选游戏，提供可选、可审阅的写入及安全恢复路径。

- [ ] 识别本地 Steam、游戏和多个用户，不猜测账号。展示准确原值／拟写入启动项，并要求明确选择目标。
- [ ] Steam 运行时阻止写入，变更前再次检查。保留无关数据、稳定 Runner 引用与既有 `%command%` 位置。
- [ ] 变更前备份原值／文件，采用原子替换、复读验证和中断恢复。记录足以仅恢复本次改动的来源信息。
- [ ] 应用和恢复前检查外部编辑。出现冲突时提示，保留当前数据和备份，不覆盖用户后来设置或其他游戏内容。
- [ ] 测试无／单个／多个用户、原启动项非空、操作期间 Steam 启动、文件损坏／只读／占用、写入失败、中断恢复、后续编辑及重复恢复。
- [ ] 验证授权的所选游戏真实会话、恢复和文件／存档完整性。不从配置写入成功扩大等待模式或成就结论。
- [ ] 以上门槛通过后才将一键应用设为默认流程；保留手动复制／恢复。

**验收：**成功表示所选设置已写入并验证。失败保留此前可用状态，或提供具体恢复路径。未解决的存档／云冲突会停止真实验收，不选择覆盖哪份进度。P4 优先于新增 Linux/SteamOS/Proton 工作，但不要求先交付可选更新器。
