## 路线原则

保持 Windows 优先的产品边界：在 WinUI 3/C# Manager 中配置游戏，再通过 Steam 调用独立 Rust Runner 启动。C# 配置服务、TOML、稳定数据路径与 CLI 继续作为基础。后续优先级是**玩家反馈 → Windows 交付与发布 → 可选更新与安全 Steam 集成 → 后续平台扩展**。

**将 v2 合入 main 是主线调整，不等于产品已经稳定发布。**安装／更新验收仍未完成。截至 **2026-10-02**，WinUI 是唯一 Manager：已按用户要求移除 Dioxus 应用、Rust `manager-core`、Dioxus Native E2E 和旧 UI 发布链。这改变了维护的实现，不代表尚未完成的 Windows 交付门槛通过。[Windows v2 设计](/SteamWrapper/zh-cn/project/design/windows-v2/)记录架构与最初阶段，[WinUI 评估](/SteamWrapper/zh-cn/project/decisions/winui3/)记录技术依据。下列里程碑明确验收顺序，不承诺日期，也不重新解释已发布版本号。限定范围的证据见[预览验收](/SteamWrapper/zh-cn/project/validation/winui/)。

- [x] 配置原子保存、替换失败保留、备份和编辑冲突验证（非协作编辑器仍有最终检查竞态）

## C. Windows 可用预览与替换门槛

- [x] 关闭 Manager 后，从真实 Steam 启动/退出并记录状态与时长；本机 Unity 游戏与 9-nine 五部通过，见 [逐游戏证据与限制](/SteamWrapper/zh-cn/project/validation/steam/)
- [x] 本机第一部 CHS 启动器先退后，实际游戏与 Runner 继续等待至普通退出；中文开场及 Steam 时长通过，仅覆盖这个实际启动器场景

这些结果不证明所有启动器兼容、成就、干净系统安装、安全更新或卸载。剩余玩家与交付门槛列在下方 P0–P2。预览继续支持手动复制启动项：生成／复制不等于写入 Steam，fixture 通过也不等于真实 Steam 时长验证。

## 后续交付里程碑

| 优先级 | 交付目标 | 依赖与完成门槛 |
| --- | --- | --- |
| P0 | 原生 UI 自动化、玩家反馈、可用界面／错误提示和本地优先的可选封面 | 当前预览；限定范围的原生、离线和网络验收 |
| P1 | 自包含每用户安装器与 portable ZIP | P0 配置流程；干净 Windows 安装／更新／移动／卸载验收 |
| P2 | WinUI 预发布与正式交付 | P1 产物；标签构建、签名／校验、双语说明与 GitHub/CNB 相同二进制 |
| P3 | 可选应用更新 | P1 替换／恢复与 P2 可信发布元数据 |
| P4 | 安全 Steam 启动项应用／恢复 | P0 配置与 P1/P2 交付保护；不依赖 P3 |
| 后续 | 其他 Windows 目标及平台扩展 | 先保证 Windows 交付可靠；新增平台分别取得证据 |

P0 反馈和 P1 打包准备可以并行。WinUI 稳定发布需要 P0–P2 验收；P3/P4 尚未完成时，手动启动项仍受支持。可选更新检查和自动 Steam 写入不能推迟配置安全修复。

**当前部署契约的版本规则：**每个新可安装载荷／清单必须使用新的协调 `MAJOR.MINOR.PATCH`。`0.2.1-preview.1` 改为 `0.2.1-preview.2` 会改变部署清单，但数字版本仍为 `0.2.1`，安装因此正确拒绝同版本不同内容。带运行序号的预览产物是独立试用构建，不是升级系列。真实 `0.2.2` 升级保留为有日期的证据；当前未签名技术源码为 `0.2.3`，首次新签名载荷必须使用新基础版本（本系列采用 `0.2.4`）。失败重试复用完全相同的不可变产物，不改写公开标签，也不放宽版本门槛。

**版本保留兼容门槛：**冻结的 `0.2.1`／`0.2.2` 部署实现会拒绝安装根目录未知文件和 JSON 字段。没有兼容元数据设计就新增健康记录文件或状态字段，可能导致回滚后的旧 Manager 无法启动。启用版本保留前必须验证真实旧二进制回滚；不能推测上一版本的历史健康状态，也不能为满足配额删除未知／隔离数据。

## P0. 玩家反馈、界面与封面

**交付目标：**改进并验收现有预览和已实现封面选项，同时保持配置和启动不依赖网络。

- [ ] 收集可复现的反馈，包括应用／Windows 版本、预期／实际行为及相关脱敏诊断。区分配置、启动器生命周期和交付问题，不要求上传存档、游戏二进制或完整 Steam 账号文件。
- [ ] 扩展实际 WinUI 应用的首个原生 UIA 回归切片，使用可丢弃的 Steam 与用户数据 fixture。补齐启动、语言切换／重启、编辑内容保留、选择器取消、保存／冲突处理及 Runner 状态的覆盖并记录限定范围证据。保留服务／契约测试；已移除的 Dioxus 测试不能证明 WinUI UI 覆盖。
- [ ] 补齐英语／简体中文原生验收，涵盖未保存输入保留、键盘、中文输入、缩放、选择器、取消和可恢复错误。
- [ ] 补齐中文／空格路径、启动失败和日志可诊断的玩家验收。保留 `job` 返回启动器状态的说明与实际后代退出码证据边界。扩展启动器结论必须有对应真实进程／游戏证据。
- [x] 封面保持**本地优先、默认离线**。优先使用自定义／本地 Steam 图片，包括新的哈希目录；按优先级验证本地候选。缺失或不可读时显示友好占位，不阻塞保存或启动。
- [x] 提供可关闭、需明确启用的**官方 Steam CDN 回退**设置。说明图片请求包含本地已知 AppID。只为本地已发现的 AppID 获取缺失封面，不上传游戏库清单、不查询账号，也不接入第三方元数据服务。
- [x] 仅允许文档列明的官方 Steam CDN HTTPS 主机，重定向也必须符合相同白名单。限制并发、请求／响应时间、下载字节和解码后的图片尺寸，拒绝不支持或损坏的内容。
- [x] 在 SteamWrapper 的 `cache` 目录保存小型配额缓存，提供过期／淘汰规则及清理入口。不覆盖自定义图片、Steam 缓存、游戏文件或配置。关闭回退后取消下载、停止新请求；有效缓存仍可离线使用，清理只影响 SteamWrapper 下载的封面。

**验收：**可重复的原生 WinUI UI 测试与更广泛的玩家试用覆盖双语、编辑和错误恢复，记录具体证据及未解决问题。封面隔离测试验证启用前及关闭后无请求、本地／自定义图片优先、偏好持久化、取消、离线／超时／404／限流、错误重定向、超大／损坏图片和缓存限制。原生检查另验证封面失败期间的流畅编辑。封面偏好、下载器与持久缓存已经实现，是限定范围的 P0 切片；上方原生 UI 自动化和更广泛的玩家验收仍未完成。实现勾选不证明所有原生或交付门槛通过。封面成功不代表 Overlay、成就或游戏兼容性通过。

控件与离线行为见[封面设置](/SteamWrapper/zh-cn/guides/configuration/#cover-settings)，请求／缓存限制见[架构](/SteamWrapper/zh-cn/development/architecture/#封面与安全边界)。官方 CDN 回退只提供尽力获取：已知 AppID 的固定竖图地址可能没有图片，新的哈希图片尤为如此；此时保留占位，不查询账号或第三方元数据服务。

## P1. Windows 安装、更新与卸载

**交付目标：**由同一应用布局生成 unpackaged、自包含的 WinUI 每用户安装器和完整 portable ZIP。

已批准的[Windows 交付方案](/SteamWrapper/zh-cn/project/design/windows-delivery/)将 P1–P3 拆为 D1a/D1b 安装与恢复、D2/D3 签名准备与发行、D4/D5 可选检查与确认更新。未签名的[Inno／C# 安装器预览](/SteamWrapper/zh-cn/guides/installer-preview/)、生命周期锁、日志／人工修复和签名保护底层已实现；内部更新认证仅使用测试夹具。下列干净客户端及完整交付勾选项仍待验收，Foundation 批准和生产已签名发布尚不可用。

- [ ] 打包 .NET、Windows App SDK、原生／本地化资源和独立 Runner。普通玩家无需安装 SDK 或准备运行时，不承诺单文件 EXE。
- [ ] Manager 按用户安装，日常安装不要求管理员权限。数据保持在 `%LOCALAPPDATA%\SteamWrapper\`，Steam 引用稳定的 `bin\SteamWrapperRunner.exe`，不引用带版本的 Manager 或解压目录。
- [ ] 在没有开发工具的干净受支持 Windows 11 x64 VM 中，验证安装、双语、首次配置、实际共享数据路径，以及关闭 Manager 后通过稳定 Runner 启动。
- [ ] 验证覆盖更新、Manager／portable 文件移动、Runner 占用、未知／不兼容版本、中断替换及回滚。保留配置、偏好、备份、日志和可工作的启动项。不降级较新的兼容 Runner，也不为替换文件停止正在运行的游戏。
- [ ] 验证仅卸载 Manager 时保留用户数据、稳定 Runner 和恢复／所有权记录。首版安装器没有删除全部数据选项或自动恢复 Steam；无法证明 Steam 引用已移除时，提供独立手动移除指引。
- [ ] 记录产物／安装体积、冷启动、支持的 Windows 版本、已测游戏及限制。提供英语与完整简体中文安装、更新、恢复、移动和移除说明。

**验收：**分别记录安装器和 portable 的结果，包括失败恢复，以及更新失败后原配置不变且仍可用。在开发机发布成功不等于干净 VM 通过。授权的真实 Steam 测试还需单独完成事前启动项／存档保护与事后完整性核对。

## P4. Windows 安全一键应用与恢复

**交付目标：**针对所选 Steam 用户的所选游戏，提供可选、可审阅的写入及安全恢复路径。

- [ ] 识别本地 Steam、游戏和多个用户，不猜测账号。展示准确原值／拟写入启动项，并要求明确选择目标。
- [ ] Steam 运行时阻止写入，变更前再次检查。保留无关数据、稳定 Runner 引用与既有 `%command%` 位置。
- [ ] 变更前备份原值／文件，采用原子替换、复读验证和中断恢复。记录足以仅恢复本次改动的来源信息。
- [ ] 应用和恢复前检查外部编辑。出现冲突时提示，保留当前数据和备份，不覆盖用户后来设置或其他游戏内容。
- [ ] 测试无／单个／多个用户、原启动项非空、操作期间 Steam 启动、文件损坏／只读／占用、写入失败、中断恢复、后续编辑及重复恢复。
- [ ] 验证授权的所选游戏真实会话、恢复和文件／存档完整性。不从配置写入成功扩大等待模式或成就结论。
- [ ] 以上门槛通过后才将一键应用设为默认流程；保留手动复制／恢复。

**验收：**成功表示所选设置已写入并验证。失败保留此前可用状态，或提供具体恢复路径。未解决的存档／云冲突会停止真实验收，不选择覆盖哪份进度。P4 优先于新增 Linux/SteamOS/Proton 工作，但不要求先交付可选更新器。
