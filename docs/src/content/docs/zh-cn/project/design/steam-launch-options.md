## 状态与交付范围

**2026-10-07 已随 `v0.2.9` 发布，限定范围的本地、公开交付及准确公开安装器验收通过。**较早的公开 `v0.2.8` 保存配置、准备稳定 Runner，并生成／复制启动选项。其选中 AppID 恢复会扫描本地账号，清除已识别的生成命令，不能重建手动粘贴覆盖前的参数。`v0.2.9` 增加明确限定单账号的应用与原值恢复流程，继续遵守 [Windows 设计](/SteamWrapper/zh-cn/project/design/windows-v2/#6-安全一键应用与恢复)及 [P4 门槛](/SteamWrapper/zh-cn/project/roadmap/#d-windows-安全一键应用与恢复)。

范围沿用 Windows 11 24H2 x64，使用平时运行 Steam 的 Windows 账号。写入设置不代表更广账号、硬件、游戏、云同步或成就保证。产品版本已协调为 `0.2.9`；后续发布仍需通过下文相应交付门槛。

## 玩家流程

1. **保存并应用到 Steam** 先校验、保存配置，再准备／验证稳定 Runner；**仅保存**只保留配置，不应用 Steam 设置，另提供独立的**复制启动项**按钮。
2. 用一个确认页显示游戏名称／AppID、Steam 账号、当前启动项和新命令。仅一个可读本地账号时展示该账号；多个账号必须明确选择，不静默默认选中。没有可读账号时不能自动应用，引导玩家先打开 Steam 登录一次，同时保留手动复制。
3. Steam 正在运行时提示正常退出，提供**重新检查**，不结束 Steam 或游戏。等待结束后重新检查，启动项已变化就让先前确认失效。
4. 备份、应用并复读所选设置，之后才显示**配置已保存，启动项已写入**。这里验证的是磁盘值，不是 Steam 客户端的内存设置。配置保存成功与应用失败分别报告：只有未发生变更时才能提示**配置已保存，尚未应用到 Steam**；替换后状态不确定则提示**无法确认应用结果，恢复资料已保留，请检查后重试或恢复**。
5. 提供**打开 Steam**，仅打开客户端，不启动游戏。玩家可使用刚才确认的 Steam 账号查看该游戏属性。日常从 Steam 游戏时不需要 Manager 常驻。

确认页解释非空旧启动项会被替换并保留，以便恢复。不猜测旧参数含义，不拼接到 `%command%`，不静默转入 Runner 参数。取消应用仍保留已保存配置，不改变 Steam。正常确认页使用英语／简体中文普通标签；存储格式、摘要和事务编号留在开发诊断中。

## 账号与设置归属

- 在 Application 增加有界只读账号发现，读取本地 `userdata`，可用时读取 `config/loginusers.vdf` 的显示字段。用夹具验证 SteamID 与账号目录映射，缺显示名称时回退账号目录标识。“最近使用”只是提示，不能据此授权写入。不添加账号网络请求，不输出凭据。
- 要求目标账号的 `localconfig.vdf` 已存在、可读，AppID 为无歧义的规范数字，配置已保存，并已验证共享稳定 Runner 路径。手工填写的 AppID 必须能唯一对应本机安装后才允许自动应用，否则保留手动方式。本地安装发现不能证明每个本地账号都拥有该游戏，因此确认页必须标明账号。
- 只修改该账号的 `UserLocalConfigStore/Software/Valve/Steam/apps/<appid>/LaunchOptions`。在已有、受支持的 `apps` 层级中支持插入缺失的游戏节点或启动项；不新建账号文件或补造缺失的顶层 Steam 层级。
- 保留注释、空白、BOM、换行、未知字段及其他游戏／账号字节。为有界语法读取器增加插入范围与正确的引号转义，不整体序列化 VDF。歧义／重复键、不支持的编码／结构、不安全路径、重解析点、只读或占用文件会停止操作。
- 保留生成契约 `"<stable-runner-path>" --appid "<appid>" -- %command%`，应用 Steam 设置不改变 TOML 序列化或 Runner 启动／等待行为。

Steam 的[官方玩家说明](https://help.steampowered.com/en/faqs/view/7D01-D2DD-D75E-2955)描述的是“属性 → 通用 → 启动选项”输入框。本地 VDF 是私有实现细节，目标路径和客户端行为必须在实际验收的 Steam 版本核实。

## 复用与代码边界

发现、配置和 Runner 就绪检查留在 `SteamWrapper.Application`；对话框、剪贴板和明确的“打开 Steam”动作留在 `SteamWrapper.Manager`。在 `SteamWrapper.Deployment` 扩展不依赖 GUI 的 Steam 设置服务，并与卸载共用。从 `SteamLaunchRestoration` 仅抽出应用／恢复需要的 VDF 范围编辑与受保护的文件变更，保留既有旧命令清除测试及精确命令规则。不增加通用事务框架、Rust 桥接、管理进程、后台监视器或服务。

预览绑定账号、AppID、数据根、已保存配置版本和当前文件字节；确认不代表允许覆盖随后改变的快照。取得既有数据锁后，在变更前重新验证配置、共享 Runner 就绪／路径、账号路径、Steam 进程状态及文件快照。与保存、移除、Runner 准备和卸载采用一致锁顺序，不重复获取调用方持有的锁。等待玩家退出 Steam 或确认对话框时不持有变更锁。

## 备份与恢复记录

沿用私有 `backups/steam-launch-options/<operation-id>/` 目录，保存小型带版本操作记录和原文件快照。记录经过验证的 Steam／账号／AppID／数据根标识、原值／原文本 token 及**原键是否存在**、写入值、有界快照摘要与操作阶段；复用原 token 前需与快照核对。正在生效的集成保留首次可恢复原值。只有当前目标仍等于可信记录的写入值，且没有未完成／冲突操作时，重复应用才幂等成功；不能将首次原值换成 Runner 命令或覆盖外部编辑。手工粘贴的相同命令且无原值记录，只能认定为原值未知的已识别集成，不能据此新建历史恢复记录。未知或歧义记录版本阻止自动写入并保留。限制记录／文件大小与枚举数量，不静默修剪恢复备份。

记录和快照必须在替换 Steam 文件前完成写入、刷盘及验证。变更前记录临时文件／相邻备份标识，使中断后可以定位，不猜测文件归属。这些是本地恢复数据，不是新增 Release 附件。真实 Steam 完整快照仅留本机，并受用户文件权限保护，不提交、不上传 CI 产物，也不在诊断中泄露内容。

采用最小操作生命周期：**已准备 → 已应用 → 正在恢复 → 已恢复**，保留取消／冲突结果，未完成操作能根据记录字节检查。恢复另行保存当前文件快照。Manager 启动或明确重试时只检查未完成记录，不改变 Steam；恢复写入要求 Steam 已退出并通过相同冲突检查。精确未变的前／后快照可判定步骤已完成或尚未开始；不一致时保留为可审阅冲突，不自动覆盖。

重开 Manager 或选择配置时重新读取目标与记录，`applied` 标记或缓存界面标签不能证明当前状态。区分磁盘写入校验与 Steam 客户端中的验证，不增加永久监视器来更新状态。

## 写入与恢复规则

1. 从确认的当前快照生成结果，写入唯一同目录临时文件，刷盘后验证。临时文件和替换备份必须位于 Steam 同一卷；实际被替换的文件在归档副本验证后才转入数据备份目录。Steam 和 LocalAppData 可能在不同盘。
2. 保留／复查源文件，在替换前再次检查 Steam，使用唯一相邻备份替换，验证实际被替换字节与结果目标；提交 `applied` 和报告成功前再检查 Steam，若已启动则保留操作及备份为待复核状态。这些检查缩小竞争窗口，不是原子阻止 Steam 启动。操作记录刷盘后才报告成功。保留既有数据／安装锁和取消检查，替换后的取消不能报告为“没有改动”。
3. 替换不等于附带原字节条件的原子比较交换。不配合锁的重命名或 Steam 启动仍能与最后一次检查竞争。实际替换前字节不符或写后验证失败时，保留所有恢复副本，停止后续写入并报告未解决状态；不能自动用整份旧文件覆盖后来的编辑。[File.Replace](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.replace?view=net-10.0) 和 [ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)定义替换／备份行为，不提供按期望内容条件替换的接口。
4. **恢复原启动项**仅针对记录的账号／AppID。读取最新文件，只有当前目标仍精确等于记录的写入值才恢复原值；其他游戏后来的变更继续保留。原键不存在时仅移除本工具插入的键，不删除包含后来数据的游戏节点。原值为空与原键不存在保持区别。
5. 目标被外部编辑后，展示当前及记录值，停止自动恢复。已恢复则无操作，不重写文件。手工粘贴且无可信原值记录时，保留另行标明的旧版**恢复普通 Steam 启动**动作，只清除精确识别的命令，不声称能恢复未知旧参数。

写前的解析／备份／冲突失败保持原文件；变更后的失败保留经过验证的恢复材料并说明不确定状态。普通文件替换不保证任意物理断电、磁盘故障或未来 Steam 格式改变时都无错误。

## 移除、卸载与兼容

新版本卸载的明确 Steam 恢复选项共用记录原值恢复规则；默认卸载仍不改 Steam 或用户数据。保留既有七项清理选项与旧标准命令清除。冲突、未知记录及未解决的相邻备份保留并提示；无法确认安全时阻止相关配置／Runner 清理，继续要求完整扫描所有账号的引用，包括配置 Key 与 AppID 别名。既有恢复备份和更新信任状态不变成通用清理对象。

共用卸载路径已让数据锁贯穿检查、恢复、最终引用检查与所选配置／Runner 删除。内部已持锁清理入口避免递归取锁，按约定顺序保留安装锁与 Runner 锁；历史分段扫描／清理不能证明这种连续持锁。

重复保存／应用、程序换安装位置、便携版移动、升级／回滚，以及旧 Manager 遇到新数据，都必须保留恢复材料。移动 Manager 不改变稳定 Runner 命令。冻结历史 helper 不被静默当作懂得来源记录的恢复器：它们清除命令后的状态应被识别为变化，不编造旧值或盲目重放。代理指南现已明确实现的 Steam 写入边界，设计要求与有日期的验收证据保留各自范围。

自动化使用可丢弃 Steam／用户数据夹具与确定的进程／失败钩子。各行为回归在实现前先观察预期失败。先跑针对性 Deployment／Application 测试；相关路径改变时跑 WinUI 与跨语言契约；共用清理改变时跑相应安装器／接力门槛，并验证双语文档。合并 CI 仅运行相关测试／编译，只有版本标签才构建发布 Setup／ZIP，不添加重复长任务，不削弱发布门槛。

既有授权的真实 galgame 测试须在操作前核对当前桌面／游戏状态，记录／恢复精确原启动项和本地文件完整性；未解决的云／存档冲突会停止验收。在 Steam 用户的 Windows 账号中从普通 Explorer 打开 Manager，核验实际共享 AppData／Runner 文件位置；开发宿主私有文件视图不证明 Steam 可访问。本地候选已通过限定的第一部应用、两次客户端重启持久显示、关闭 Manager 启动及记录非空原值恢复；[测试](/SteamWrapper/zh-cn/development/testing/#steam-integration-029-2026-10-07)记录非存档文件不变、引擎存档自然更新和用户精确原命令复位。结论证明所测客户端持久性，不保证未来任意版本。最终本地发布目录的隔离安装器／选项、全部双语原生清理选择、实际更新接力及 18 步干净沙盒升级也已通过。准确标签公开附件／四份签名更新源、下载的 NativeAOT Host 两项用例，以及准确公开 `0.2.8 → 0.2.9` 的 18 步干净沙盒升级分别通过。公开与本地候选二进制属于不同产物；公开安装器夹具不增加真实游戏、新普通账号、双用户或硬件覆盖。继续提供手动复制及既有安全备用方式。
